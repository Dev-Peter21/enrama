# G01 Local Assets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement issue #8's bounded image validation and unchanged staging copy on develop, independently of renderer, builder and CLI.

**Architecture:** A small core asset API prepares immutable byte snapshots and field bindings; private image and filesystem modules validate decoded content and confined file operations. A separate structured error type keeps field failures and operational severity without modifying C02's API.

**Tech Stack:** Python 3.12+, Pillow 13.0.0 runtime, existing uv/Hatchling/pytest/Ruff/strict mypy, unchanged seven-job CI matrix.

**Spec:** [Approved G01 contract](../../assets.md), [C01](../../configuration.md), [C02](../../yaml-loader.md), [F01](../../cli-contract.md).

## Global Constraints

- User authorized implementation directly in develop; reuse the clean normal checkout. Native execution, one independent final review, no additional handoff checkpoint.
- Version 0.1.0.dev0; no renderer, builder, CLI, themes/icons, PyPI/release/deployment. Leave issue #8 open for maintainer acceptance.
- Only profile.avatar/site.favicon/site.og_image. PNG/JPEG/static WebP for avatar/OG; PNG/ICO favicon. Case-insensitive input extensions, canonical lowercase output.
- Limits: 5,242,880 bytes avatar/OG, 1,048,576 favicon, 10,485,760 unique bytes total; 8,192 per side and 16,000,000 pixels avatar/OG; 1,024 per side PNG favicon; 16 actual ICO entries each ≤256 per side. Positive dimensions, exact bounds accepted.
- No transformations/metadata stripping. Reject animation containers even one-frame. Verify structure and decode every ICO entry with no permissive truncation.
- Resolve canonical client root from selected source parent; use C01 lexical rules/portable separators. Reject every internal symlink and nonregular source, output/reserved sources; no parent-ancestor symlink ban above root.
- Paths assets/client/<full lowercase sha256>.<canonical extension>. Compare bytes before deduplicating, immutable validated snapshots for later copy.
- Prepare writes nothing; copy only into an explicitly reserved, existing real staging directory inside client root, outside dist and disjoint from original sources. Staging is caller-owned; no publication/cleanup/locking implementation.
- Source/input failures vs operational/staging conflicts remain distinct. Fixed field order, cap20/honest counts, no guessed coordinates/raw exceptions or bytes; no printing/exiting. Mixed expected failures classified operational.
- Preserve C01/C02 and checked JSON schema. Add Pillow only when used, extend explicit archives and actual installed consumer coverage; retain uv/build hash discipline and matrix.

## Review Focus

- Filesystem substitution and reserved-path aliases: no special-file blocking, symlink escape or original overwrite. Add real link/special-file and deterministic race probes in Task2/3.
- ICO duplicated sizes/alternate entries and oversized embedded headers: validate every raw directory entry before decoding, not only Pillow's default largest. Task1 pins duplicate corrupt and dimension mismatch cases.
- Animation with one frame plus malformed containers: explicit APNG/WebP container inspection complements decoder flags. Task1 pins actual one-frame fixtures.
- Data provenance: role-specific rechecks, hash collision and changed source must never bypass checks or reopen unchecked copy data. Task2/3 pin these cases.
- Library state/failures: missing required codecs, decoder OSError vs source I/O, interrupts and unexpected defects must not masquerade as invalid images. Task1/2 pin failures and global-state preservation.
