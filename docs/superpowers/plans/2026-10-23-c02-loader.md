# C02 Safe YAML Loader Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement issue #6's bounded safe YAML loader and structured diagnostics on develop.

**Architecture:** Parse PyYAML SafeLoader events into a bounded representation with no YAML constructors/resolvers or shared references. Construct the approved plain-data subset only after syntax/structure limits pass, record source locations, and delegate semantic validation to C01. A separate diagnostic module provides safe English text without printing or exiting.

**Tech Stack:** Python >=3.12, PyYAML 6.0.3, types-PyYAML 6.0.12.20260906 (dev only), Pydantic, uv 0.13.5, pytest/Ruff/strict mypy.

**Spec:** [Accepted C02 contract](../../yaml-loader.md), [C01](../../configuration.md), [F01](../../cli-contract.md).

## Global Constraints

- Existing clean checkout on `develop`, base `87d17e4`; version remains `0.1.0.dev0`. Implement natively under the user's existing instruction, with one fresh final reviewer.
- No CLI, generator, JSON Schema, round-trip writer, asset I/O, network validation, PyPI publication, or deployment.
- UTF-8 with optional initial BOM; exactly one nonempty mapping document, string keys, no decoded duplicate keys, anchors, aliases, merges, custom/Python/unsupported tags.
- Enrama-only scalar policy: lowercase true/false booleans; null/~ /omitted values null; JSON-style decimal integers/finite floats; other ordinary scalars strings. Quoting preserves strings unless a supported explicit standard tag selects a constrained kind.
- Fixed raw limit 1,048,576 bytes including BOM/comments; 32 container levels with root1;10,000 nodes including scalar keys/values;20 diagnostics with exact total/omitted counts. Never expose configurable bypasses.
- Enforce size on actual reads and node/depth budgets while consuming parser events, before plain Python-data construction. Reuse C01 for all field rules.
- Structured failure includes category, selected file, key/index location, optional 1-based position, English message/hint, and related locations. Lists use 0-based indexes. No raw values/excerpts/exception payloads or invented coordinates.
- Stable source/field/category ordering; suppress dependent-default bookkeeping; keep root C01 errors at `$` and mark missing-field coordinates as parent positions.
- Loader returns data or raises a structured expected error; never prints/exits, swallows interruption/internal defects, changes cwd, or writes files. F01 category-to-exit mapping remains future CLI work.
- Preserve explicit archive inclusion, no dev tools in runtime, isolated wheel/sdist probes and full existing CI matrix. PyYAML lacks a cp315 wheel: hash-pin required setuptools/Cython build inputs and test dependency source installation rather than skipping Python 3.15.

## Review Focus

- Parser state must reject malicious tags/anchors/recursive aliases without executing any constructor, even when globally registered with SafeLoader.
- Exact budgets must count scalar keys and nested containers and fail while reading/parsing, not after a giant tree is constructed.
- Source marks must distinguish duplicate occurrences, repeated values, missing-parent positions and global errors without searching message text.
- Diagnostics must not leak input through Pydantic context, parser snippets, Exception repr, or unsafe filename/field display; mixed key/index sorting must remain deterministic.
- Real file failures/interruption and PyYAML's Python 3.15 source-build fallback must stay correct in isolated installed consumers, with no client asset/file-output effects.
