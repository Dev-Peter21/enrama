# C01 YAML v1 Models Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement issue #5's pure Pydantic v2 models and validation against the accepted YAML v1 contract.

**Architecture:** Six strict models share focused URL, language, and lexical-path validators and immutable presentation catalogs. Language validation reads the pinned langcodes distribution's bundled IANA registry once at import, then validates from memory without touching client files or the network. Existing explicit packaging and isolated consumer tests grow with the modules.

**Tech Stack:** Python 3.12+, Pydantic 2.14.1, langcodes 3.5.1 (registry data only), uv 0.13.5, pytest, Ruff, strict mypy.

**Spec:** [Accepted YAML v1 contract](../../configuration.md).

## Global Constraints

- Work directly on the existing clean `develop` checkout as requested; keep version `0.1.0.dev0`.
- No YAML loader, CLI, generator, asset I/O, SVG assets, generated JSON Schema, PyPI publication, or deployment.
- Required root fields: integer `schema_version: 1`, `site`, `profile`; default empty links/socials and minimal theme.
- Strict types and forbidden unknown keys recursively; null only for the five documented nullable fields.
- Text limits: titles/names/labels 1–100; description 1–300; bio 0–300, measured after trimming.
- IDs `[a-z][a-z0-9-]{0,63}`, globally unique across up to 100 links/20 socials, including disabled entries; preserve order.
- Colors `#[0-9A-Fa-f]{6}`; defaults `#2563EB`, `#FFFFFF`, `#252525` for both themes.
- Site/social URLs HTTPS only; link URLs HTTPS/HTTP/mailto/tel; maximum 2048 characters; preserve original destinations and do not use network validation.
- Language accepts registered primary/script/region/variants in the documented subset and normalizes case only.
- Nine platforms select icon/default label only; twelve general link icons; no domain binding or social icon override.
- Add only used runtime dependencies. Pin registry-data dependency exactly so consumers use the same snapshot; update lock, explicit archive inclusion and consumer checks together.

## Review Focus

- A URL parser may repair malformed authorities or ignore controls: reject raw input defects before parsing and preserve accepted input.
- Language helpers may normalize aliases or accept a subtag in the wrong category: check actual bundled IANA records by type, excluding private-use ranges, without alias replacement.
- Explicit null and invalid platform data must produce ValidationError rather than bypassing defaults or raising KeyError in label derivation.
- Windows/UNC paths and case variants of the reserved output directory must not pass a platform-dependent lexical check.
- An editable install may hide missing package files/data or accidental dev requirements: build/install both archives independently and exercise models outside checkout.
