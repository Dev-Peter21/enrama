## Executed checks

The initial artifact test failed before package configuration existed: uv
reported that the directory was not a Python project. After implementation:

- `uv sync --locked`: synchronized the development environment on Python 3.12.
- `uv run --locked ruff check .`: passed.
- `uv run --locked ruff format --check .`: passed.
- `uv run --locked mypy src tests`: passed, three source files, strict mode.
- `uv run --locked pytest`: **5 passed**.
- `uv build --python 3.12 --build-constraint build-constraints.txt --require-build-hashes`:
  produced both the sdist and wheel from that sdist.
- The documented constraints-regeneration recipe reproduced the committed file.
- `git diff --check`: passed.

The five tests exercise:

1. Wheel installation in a new isolated consumer environment.
2. Sdist installation in a separate isolated consumer environment.
3. Exact archive contents, synthetic private-file exclusion, and byte-identical
   hashes across two builds from the same inputs.
4. Rejection of a missing lockfile without creating one.
5. Rejection of a stale lockfile without modifying it.

Each installation runs outside the checkout, removes `PYTHONPATH`/virtualenv
selection overrides, and invokes consumer Python with `-I`. The installed
module resolves to that environment's `site-packages`. Distribution metadata
reports `enrama`, `0.1.0.dev0`, `>=3.12`, and MIT with the license text included.
Each consumer contains only Enrama: no runtime dependencies or console scripts.

The hash-verification option emits uv's experimental-feature warning; it is
supported by the pinned version and the build succeeds with verification enabled.
Archive repeatability was tested on this environment; cross-platform identical
archive hashes have not been established.
