# G02 verification

Status: **implemented on develop, awaiting maintainer acceptance**, following
explicit authorization on 2026-10-24. [Issue #9](https://github.com/Dev-Peter21/enrama/issues/9)
remains open. The [approved contract](../rendering.md) and
[implementation plan](../superpowers/plans/2026-10-24-g02-rendering.md) define scope.

## Delivered behavior

- Public `render_html(config, prepared) -> str` consumes C01 data and matching
  G01 snapshots and returns a complete shared HTML document in memory.
- In-memory image relationship checks reject missing/extra/duplicate/mismatched
  bindings, missing/duplicate asset paths and noncanonical/role-incompatible paths.
  No YAML reload, image reopening, byte hashing/decoding, copying or client I/O.
- One fixed packaged Jinja2 template, explicit autoescape and StrictUndefined,
  primitive presentation context and structured safe English `RenderError`.
- Shared semantic HTML for both accepted theme names: document language, charset,
  viewport, one main/profile h1, optional decorative avatar/bio and independently
  ordered enabled links/socials with visible accessible labels.
- Conditional metadata, directory-form public URLs, relative local image/favicon
  references and unmodified validated destinations in the same browsing context.
- Real package-resource I/O failures are operational; integration/template defects
  are internal. Interrupts propagate. No partial HTML or terminal/process output.
- Explicit wheel/sdist inventories include both render helpers, renderer and base
  template. Isolated installed consumers render both accepted names, check parsed
  metadata/escaping/destinations and restrict renderer I/O to its package resource.

No builder, output lifecycle, product CLI/preview, final theme presentation,
CSS/icons/fonts, schema change, version increment, release, PyPI upload or client
site deployment was implemented. Static-server test scaffolding is test-only.

## Local environment and test-first evidence

CPython **3.12.15**, macOS arm64; uv **0.13.5**. Jinja2 **3.1.6** and MarkupSafe
**3.0.4** are the locked installed versions. Runtime metadata adds
`jinja2>=3.1.6,<4`; both dependencies provide typing, without new stubs or build
constraints. Compatible dependency resolutions remain governed by the lock for
repository development and package metadata for downstream consumers.

- Clean network-enabled baseline: **620 passed**.
- Binding stage: **22 missing-feature failures**, then **22 passed**; whole suite
  **642 passed**. A test-relative import was corrected before the missing-feature
  run; it was a collection mistake, not a production failure.
- Renderer stage: **48 missing-feature failures**, then **48 passed**; whole suite
  **690 passed**. Covers parsed HTML, metadata combinations, hostile plain text,
  URI spelling, no source reopening/mutation, resource defects/I/O and interrupts.
- Focused installed/hosting verification: **6 passed**: three isolated consumers
  (wheel, sdist, wheel with an actual PyYAML source build), explicit archive
  inventory/repeatability, and two root/subpath HTTP resource cases.

The three installed consumers render both theme names and retain actual Jinja2 /
MarkupSafe versions in their JSON output. An audit hook permits only the fixed
installed template read and rejects other opens/network during a repeated render.
Existing C01/C02 no-I/O model/parse checks remain intact. HTTP tests serve only
synthetic staged files through Python's plain static server and request the HTML,
avatar and favicon; production canonical metadata points at a different host and
prefix, proving local resources do not depend on it.

## Full validation, review and remote matrix

The full local suite passed **694 tests**, zero failures/errors/skips: the
620-case baseline plus **74 G02 cases** (22 bindings, 50 renderer, two HTTP).
The three existing installed-consumer tests now also exercise shared rendering.
Executed locked sync, Ruff lint/format, strict mypy, schema drift check, full JUnit
suite and constrained wheel/sdist build. Both archives contain the exact packaged
base template and renderer modules; explicit inventory/repeatability tests pass.

```console
uv sync --locked
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked mypy src tests scripts
uv run --locked python scripts/schema.py --check
uv run --locked pytest --junitxml=reports/g02/local-pytest.xml -q
uv build --python 3.12 --out-dir reports/g02/local-dist --build-constraint build-constraints.txt --require-build-hashes
```

One independent read-only whole-change review ran all 70 original binding/render
cases and additionally verified validated Markup text escapes safely. It found no
security or integration defect and one small LF serialization discrepancy: Jinja
normalizes template-source newlines, not interpolated CRLF/CR text. Because LF
is an explicit output contract, this was corrected before delivery. Two tests
through the real C02/C01 path failed first, then passed after normalizing the
returned HTML; the input model retains its original text. The complete suite
then passed **694 tests**. No deferred minor remains.

Review boundaries were retained: byte authenticity/rehashing belongs to G01;
unused canonical snapshots need not be rejected because only checked bindings
reach HTML; final themes, builder/CLI/preview remain outside G02. Expanding those
boundaries would duplicate validation or change scope. Remote compatibility is
judged only from the actual matrix, not inferred from local results.
