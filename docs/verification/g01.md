## Delivered behavior

- Read-only `prepare_assets` resolves the client root from the selected source,
  rejects internal links, nonregular files and reserved input paths, bounds actual
  reads and returns immutable validated bytes and field bindings.
- Pillow 13.0.0 verifies/decodes accepted role-specific PNG/JPEG/static WebP/ICO.
  Byte, side/pixel and actual ICO-entry limits are enforced. One-frame animation
  containers are rejected. Every ICO entry is checked, including duplicate sizes
  and embedded payload dimensions before eager decoding.
- Full original-byte SHA-256 yields stable `assets/client/<digest>.<extension>`
  paths. Exact bytes, not hash equality alone, govern content reuse and collisions.
- `copy_assets` accepts only an existing exact reserved staging directory. It
  copies the prepared snapshot even after the original changes/disappears, uses
  exclusive creation and verifies identical existing files without truncation.
- Structured English `AssetError` diagnostics preserve field/global order,
  distinguish expected input vs operational failures, escape displayed references
  and expose honest retained/total/omitted counts. No printing/process exit.
- Public preparation/snapshots/copy/error APIs are exported from `enrama.core`.
  Explicit wheel/sdist inventories include all five core modules. Installed
  consumers outside checkout exercise every accepted format and required codec.

C01/C02, the checked JSON Schema and build constraints remain unchanged. No
renderer, builder/manifest/publication/cleanup/locking, product CLI, image
transformation, theme/icon/editor, package release, PyPI upload or deployment
was implemented. Caller-created synthetic staging in tests is not a builder.

## Boundaries and review

POSIX file operations use anchored no-follow directory descriptors. Windows uses
reparse/type/identity checks around full-path operations; no claim of an OS
sandbox against concurrent hostile filesystem mutation is made. G03 still owns
coordination and published-output protection. Partial staging after a copy I/O
failure is preserved for caller-managed safe cleanup; original source and prior
published output are not cleanup targets.

Decoder acceptance is not sanitization or exhaustive browser compatibility.
Original metadata/orientation are retained. Trusted Python callers use the
immutable preparation records; those records are not deserialized authorizations.
Missing required codecs or permissive externally configured truncated decoding
are environment failures, not invalid client images.

## Independent review and corrections

A fresh whole-change reviewer inspected `3f5e922..1141358`, independently passed
all 102 then-existing G01 tests and ran isolated boundary probes. No Critical
issue was reported. Three Important findings and the lower-impact digest
invariant were addressed in one fix pass, each observed RED→GREEN:

- Four WebP variants (animated, extended, lossy VP8 and lossless VP8L) now inspect
  actual container/bitstream dimensions and animation **before the first native
  decoder constructor**, which can allocate its canvas during Image.open.
- Case and Unicode-normalization aliases on the actual macOS filesystem no
  longer bypass reserved paths. Existing filesystem identities supplement lexical
  containment, without folding genuinely distinct case-sensitive names.
- A staging root deleted immediately before writing is no longer recreated.
  Only namespace directories strictly below the existing caller-owned root may
  be created; missing staging produces an operational failure.
- Forced equal digest across PNG/JPEG now fails explicitly despite distinct
  extensions. Digest-to-bytes comparison precedes public-path construction/reuse.
  The explicit approved invariant was completed rather than left as optional polish.

The eight new regressions bring the focused suite to 110 and full local suite to
620. No deferred minors remain. Actual permission-denied source/staging probes
also produced read_error/write_error operational outcomes while preserving
original bytes and leaving staging empty; raw local evidence is retained at
`reports/g01/local-permission-probes.json` (ignored). A real temporary Unix
socket was also rejected as unsafe_path/invalid_input without a special-file
read; evidence is in `reports/g01/local-socket-probe.json`. The sandbox denied
creating that local socket, so the successful probe used authorized escalation.

Review scope rulings and consequences:

- Compatibility requires actual remote jobs/reports; until those pass, upstream
  support metadata is not a full-matrix claim. Maintainer acceptance remains a
  separate gate even after CI succeeds.
- Native Windows concurrent-substitution guarantees cannot be established by a
  macOS reviewer. CI covers supported ordinary behavior; fallback reparse/type/
  identity checks do not promise adversarial-race isolation.
- Continuous hostile filesystem rewriting is outside the approved sandbox
  guarantee; G03 must coordinate output operations. The concrete staging
  recreation defect above is fixed rather than excluded by that boundary.
- Published-site integrity, rollback and cleanup belong to G03. This asset API
  cannot publish/recover a complete site or clean arbitrary working trees.
- Decoder acceptance is not exhaustive corruption detection/browser sanitization;
  tolerated bytes and browser differences can remain while originals are preserved.
- PreparedAssets records are for trusted in-process Python callers, not untrusted
  deserialized authorizations or a boundary confining hostile Python code.
