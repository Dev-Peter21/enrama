## Delivered behavior

- Read-only `prepare_assets` resolves the client root from the selected source,
  rejects internal links, nonregular files and reserved input paths, bounds actual
  reads and returns immutable validated bytes and field bindings.
- Pillow 13.0.0 verifies/decodes accepted role-specific PNG/JPEG/static WebP/ICO.
  Byte, side/pixel and actual ICO-entry limits are enforced. One-frame animation
  containers are rejected. Every ICO entry is checked, including duplicate sizes
  and embedded payload dimensions before eager decoding.
- Full original-byte SHA-256 yields stable `assets/client/<digest>.<extension>`
  paths. Exact bytes, not hash equality alone, govern content reuse and collisions.
- `copy_assets` accepts only an existing exact reserved staging directory. It
  copies the prepared snapshot even after the original changes/disappears, uses
  exclusive creation and verifies identical existing files without truncation.
- Structured English `AssetError` diagnostics preserve field/global order,
  distinguish expected input vs operational failures, escape displayed references
  and expose honest retained/total/omitted counts. No printing/process exit.
- Public preparation/snapshots/copy/error APIs are exported from `enrama.core`.
  Explicit wheel/sdist inventories include all five core modules. Installed
  consumers outside checkout exercise every accepted format and required codec.

C01/C02, the checked JSON Schema and build constraints remain unchanged. No
renderer, builder/manifest/publication/cleanup/locking, product CLI, image
transformation, theme/icon/editor, package release, PyPI upload or deployment
was implemented. Caller-created synthetic staging in tests is not a builder.

A fixture correction was necessary: Pillow's one-frame PNG saver emitted a

Additional RED→GREEN regressions:

- A real self-referential link raised pathlib's old RuntimeError rather than an
  expected unsafe-path failure; it now maps correctly without exposing a traceback.
- A deterministic ELOOP injection models newer pathlib behavior and verifies the
  same input classification across the supported interpreter series.
- An oversized JPEG header emitted a Pillow decompression warning during format
  detection; the local warning scope now classifies it as a bounded input failure
  without leaking a framework warning or altering decoder globals.

The full suite passed **612 tests**: baseline 510 plus **102 G01 cases**. There
were zero local failures/errors/skips. Unit cases exercise real image payloads,
exact/over limits, snapshot preservation, source/working path rules, a FIFO
subprocess timeout guard, source-parent replacement, destination conflicts,
hardlinks and unexpected/interrupted failures. Fault injection is confined to
otherwise hard-to-reproduce OS/decoder errors and forced digest collisions.

Installed wheel, sdist and inherited PyYAML-source consumer probes create their

## Boundaries and review

POSIX file operations use anchored no-follow directory descriptors. Windows uses
reparse/type/identity checks around full-path operations; no claim of an OS
sandbox against concurrent hostile filesystem mutation is made. G03 still owns
coordination and published-output protection. Partial staging after a copy I/O
failure is preserved for caller-managed safe cleanup; original source and prior
published output are not cleanup targets.

Decoder acceptance is not sanitization or exhaustive browser compatibility.
Original metadata/orientation are retained. Trusted Python callers use the
immutable preparation records; those records are not deserialized authorizations.
Missing required codecs or permissive externally configured truncated decoding
are environment failures, not invalid client images.
