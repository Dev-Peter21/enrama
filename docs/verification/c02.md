## Delivered behavior

- Public `parse_config(bytes, *, source=...)` and `load_config(path=...)` return
  the existing C01 model or raise a structured `ConfigurationError`.
- Raw UTF-8/BOM size check, exactly one mapping document, string/duplicate-key
  enforcement, and rejection of anchors, aliases, merges and unsupported tags.
- Explicit scalar policy without PyYAML constructors or global resolver changes.
  Parser events are limited to 32 container levels and 10,000 nodes before
  Enrama constructs plain mappings/lists. The read is bounded to 1,048,577 bytes.
- C01 validates semantic fields; source-aware English diagnostics retain at most
  20 actionable errors with exact total/omitted counts. Missing fields annotate
  their parent; global errors remain honestly unlocated. No input values,
  parser excerpts, validator context, or raw I/O payloads enter rendered errors.
- Read-only selection of one regular file; no parent search, cwd changes,
  referenced-asset opens, output, network access, printing, or exits.
  Interruption/internal defects propagate and descriptors close on failure.
- Exact wheel/sdist inclusion and installed consumer coverage, including a cold
  dependency source build using hash-verified build inputs.

CLI, generator, generated JSON Schema, asset existence/format checks and editor
remain later tasks. Version stays `0.1.0.dev0`; no PyPI upload or release occurs.

Tests compare documented examples with independent model fixtures; exercise
exact limits and one-over cases (including stale size metadata/partial reads),
SafeLoader constructor isolation, dangerous URLs, duplicate source marks,
repeated values, missing parents, global errors, 20/21/27 diagnostics,
control-character escaping, dependent-default suppression, regular-file checks,
cleanup/interruption and injected defects. The FIFO test is platform-specific
and skips where the OS does not provide FIFOs.

Each installed consumer uses isolated Python (`-I`) outside the checkout,
verifies import location and runtime metadata, loads a selected YAML without
writing outputs, and exercises byte parsing/errors with an audit hook rejecting
all file opens/socket operations. Accepted missing avatar references demonstrate
that asset I/O is still deferred. Builds are repeatable and exclude synthetic
private files, unrelated modules and developer dependencies. There is no CLI
entry point or generated JSON Schema in either archive.

## Review and remote CI

The fresh independent review of `87d17e4..5fd7488` found **no actionable
findings**. The reviewer independently ran **124 C02 unit tests**, plus tag
directive and invalid-Unicode probes, without changing the checkout. No minor
findings were deferred.

Review scope rulings (including the consequence if the boundary is insufficient):

- CLI exit codes/terminal behavior remain future CLI work under the explicit
  contract. Consequence: C02 does not prove future terminal integration.
- Asset checks, generation, JSON Schema, publication and deployment remain
  excluded by the user's instruction. Consequence: this slice does not prove a
  generated/published client site.
- An embedded-NUL programmatic path argument raises `ValueError`: it cannot
  represent a filesystem path or OS argv entry. Consequence: such API misuse
  does not receive `ConfigurationError`.
- `from None` suppresses original exceptions in normal error display; deliberate
  inspection of `__context__`/traceback locals can inspect original input.
  The approved boundary protects diagnostic fields, `str`/`repr`, and normal
  display rather than an in-process debugger. Consequence: introspecting
  consumers/debuggers must treat that original data as untrusted/private.
- Python 3.15 source builds and cross-platform claims are gated on actual remote
  jobs and retained reports. Consequence: compatibility cannot be claimed from
  local macOS/3.12 evidence alone.
